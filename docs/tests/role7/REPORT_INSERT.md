# Testing section for the team report

The testing contribution uses the actual Java repository and the original requirement identifiers. Forty automated cases were executed on 06 November 2026 at 21:43 CAT: 25 client cases, 11 server cases and four standalone prototype cases. Thirty passed and ten failed. The dependency-free Java runner compiles selected production-core and test sources, then runs each case in an isolated JVM with a private data directory. Raw logs, JSON results, JUnit-format XML and source hashes accompany the tests. The full Swing GUI, external database dependency and live networking are outside this execution.

Passing tests cover filtering, offline selection, plan validation, local save and queueing, autosave restoration, idempotent save, reconnect, retry, partial acknowledgement, batch limits, server validation boundaries and codecs. J09 and P03 are genuine separate-process restart checks: a writer JVM closes and a new reader JVM verifies the stored desktop plan/draft/outbox files and the prototype text outbox. They establish normal file persistence, not power-loss atomicity or server SQLite persistence.

The ten failures are reported in DEFECT_LOG.md. Highest priority findings include unquoted strings in the desktop JSON payload, rejected IDs parsed as accepted, an orphan queue record after a failed plan write and a SYNCING record excluded from retry after reload. Other findings concern corrupted stored object types, blank safety content, missing explicit Swing label associations, incomplete FR4 server validation and a prototype outbox failure that does not signal its caller. A compatibility test also records that the desktop Ballerina/JSON path and Java-server/standalone-prototype path cannot be mixed without adaptation; it does not establish that the correctly paired standalone prototype cannot sync.

Recommended changes are to agree and document the final client/server contract, parse payloads and acknowledgements structurally, make plan/outbox writes recoverable, restore interrupted sync records to a retryable state, validate the content of required plan elements and bind form labels to controls. These are test-supported redesign recommendations. No production fixes, participant feedback or completed before/after redesign are claimed by this testing handover. Role 8 and the developers must record actual changes and retest them.

Keyboard, screen-reader, text-scaling, exit-warning and live interrupted-network checks remain unexecuted. The Java server SQLite restart check is blocked here because its JDBC dependency and Maven are unavailable. Existing PASS statements in the server README are treated as teammate claims, not independent results from this run. The traceability matrix links each executed case to FR1-FR6, QR1, QR2, SUS1 or AC1, its actual component, result and defect. FR7/FR8 remain outside this tester scope.
